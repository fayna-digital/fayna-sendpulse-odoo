# Мульти-агентний конвеєр розробки (на зовнішніх ШІ — економія Claude-токенів)

> Як ми будуємо й перевіряємо фічі командою ШІ-агентів зі стеками, до консенсусу.
> Дешеву масову роботу (рев'ю/тести × багато раундів) несуть зовнішні API
> (DeepSeek / GLM / Gemini), Claude — лише точкова реалізація та інтеграція.

## Ролі (мінімум 3 агенти кожної)
| Роль | Стек | Що робить |
|------|------|-----------|
| Архітектор | Odoo 17 | ТЗ: моделі/методи, data/views, конфіг, RODO, ризики |
| Розробник | Python/ORM, QWeb/XML, OWL | пропонує повну реалізацію (diff/файли) |
| Tech-lead / суддя | — | обирає найкращу пропозицію, вказує що підмішати |
| Інтегратор | — | реально пише код на гілці |
| Рецензент | Odoo 17 review | approve + issues (blocker/major/minor) |
| QA / тестер | Odoo 17 static | py_compile, XML, ref-цілісність, логіка |
| Tech-writer | — | оновлює доки/CHANGELOG |

## Цикл (до консенсусу)
```
Дизайн:   3 архітектори → синтез ТЗ (docs/TZ_*.md)
Реалізація: 3 девелопери → суддя обирає → інтегратор пише на гілці feature/*
Рев'ю-цикл:  3 рецензенти → якщо НЕ всі approve → фікс → знову (кап 3 раунди)
Тест-цикл:   3 QA (реальні статичні гейти) → якщо НЕ всі pass → фікс → знову
Манул:     інструкція + CHANGELOG
→ STAGING (жива Odoo) → PROD — ЛИШЕ з «ок» людини (#4ZONES)
```

## Інструменти
- `docs-sorter/team_llm.py` — generic чат на всіх провайдерах (DeepSeek/GLM/Gemini/Qwen/Moonshot/OpenAI), ланцюг fallback. Ключі: `~/.secrets/ai_apis.env`.
- `docs-sorter/team_review.py <repo> <base> [review|test]` — панель 3 рецензентів/тестерів по `git diff`, друкує вердикти JSON.

```bash
python3 team_review.py ~/Developer/Fayna-Projects/fayna-sendpulse-odoo main review
python3 team_review.py ~/Developer/Fayna-Projects/fayna-sendpulse-odoo main test
```

## Критерії консенсусу
- **approve/pass = true у ВСІХ** → проходимо далі.
- Якщо дисидент дає **хибні спрацювання** (false positives) — реалізатор **звіряє кожне** (verify, не застосовувати наосліп) і фіксує лише реальні. Хибні документуються, не «латаються» оборонним мотлохом.
- Кап раундів (3), щоб не крутитись вічно; якщо кап досягнуто — лог + ескалація людині.

## Межі (важливо, чесно)
- Зовнішні агенти роблять **статичну** перевірку + рев'ю. **Реальний тест — на staging** (запущена Odoo: встановити модуль, натиснути кнопку, перевірити доставку листа й лінк).
- Прод — **тільки** після staging і явного «ок» людини. Жодних правок на сервері (#4ZONES).
- Секрети — лише в `ir.config_parameter`(password=True) / `~/.secrets`, ніколи в чат/git.
