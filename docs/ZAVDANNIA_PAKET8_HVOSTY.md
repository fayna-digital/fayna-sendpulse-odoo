# Пакет 8 — хвости після приймання Пакета 7

Дві дрібні за обсягом правки, знайдені при незалежному прийманні Пакета 7
(31.08.2026). Обсяг маленький, але одна з них піде на **платну сторінку
модуля**, тому це не косметика.

Репо: `fayna-sendpulse-odoo`, гілка `feature/direct-transport`, Odoo 17.
Модуль: **78 тестів зелені** (перевірено незалежним прогоном), версія `17.0.1.4.0`.

# И-1 · Опис у маніфесті обіцяє те, чого модуль не робить

**Файл:** `__manifest__.py`, ключ `description` (рядки 5-15)

Цей текст іде **на сторінку модуля в Apps Store**, тобто його читає покупець
за 49 EUR як специфікацію. Зараз він неточний у двох місцях.

## Проблема А — рекламується схема, яку ми прибрали

Рядок 13:

    - Telegram webhook controller (/bridge/telegram/webhook/<token>)

Реальний роут — `/bridge/telegram/webhook/<webhook_id>` (звірено grep по
`controllers/main.py`). Тобто опис рекламує **стару небезпечну** схему з
bot-токеном у шляху URL — рівно ту, яку ми цілим завданням Б-2 звідти
прибирали, бо вона текла в nginx-логи 34 рази.

**Що зробити:** привести до фактичного роуту. Заодно згадати, що підключення
використовує `secret_token` Telegram — це перевага, і покупець має її бачити.

## Проблема Б — сім каналів заявлені як рівноцінні

Перший абзац перелічує Telegram, Instagram, Facebook/Messenger, Viber,
WhatsApp, LiveChat, TikTok і каже «Fully autonomous».

Фактичний стан, зведений з нашої ж роботи:

| Канал | Що справді є |
|---|---|
| **Telegram** | повний шлях: майстер підключення, `secret_token`, вебхук, відправка, ретраї — перевірено живим тестом |
| Messenger / Instagram / WhatsApp | обробник вебхука + HMAC-перевірка є; **OAuth не реалізовано** — у майстрі прямо сказано, що підключає адміністратор вручну |
| Viber | обробник є, але схема підпису **не підтверджена** жодною чужою реалізацією |
| TikTok | обробник є, механізм автентифікації **невідомий**, стоїть заглушка на спільному секреті |
| LiveChat | обробник є, механізм **не досліджувався** |

**Що зробити:** переписати перелік чесно — виділити Telegram як повністю
робочий, решту подати як те, чим вони є (обробники вебхуків, підключення
адміністратором). Не викидати їх зі списку, але й не обіцяти рівноцінності.

🔴 Не «пом'якшувати» формулюваннями на кшталт «підтримка в розробці» без
конкретики: покупець має розуміти, що саме отримає сьогодні.

Заодно додати в опис те, чого там **немає**, хоч воно зроблено: галерея
«Підключити канали» (`channel.provider`), UI оператора (розмови, журнал),
маскування секретів у логах.

## Verify для И-1

- пошук `<token>` у `__manifest__.py` → **нуль**;
- опис відповідає таблиці вище — звірити рядок за рядком;
- модуль встановлюється, тести зелені.

# И-2 · `ruff format` — разове прибирання 11 файлів

**Файли:** ті, що назве сам `ruff`

`ruff format --check` по модулю падає на **11 файлах**: подвійні лапки замість
одинарних, які задані в `pyproject.toml`
(`[tool.ruff.format] quote-style = "single"`). `ruff check` при цьому чистий —
тому «лінт ок» у звітах формально не брехня, просто формат не перевірявся.

**Що зробити:** прогнати `ruff format` по модулю. Це механічна операція, вона
нічого не ламає — але після неї **обов'язково** прогін тестів, бо диф зачепить
багато файлів і сховає в собі будь-яку випадкову зміну.

## Verify для И-2

- `ruff format --check` по модулю → **0 файлів до переформатування**;
- `ruff check` → All checks passed;
- прогін: `0 failed, 0 error(s) of N tests`, exit 0;
- у диффі **лише** лапки й відступи — жодної зміни логіки.

# 🔍 Чому лапки поверталися тричі — корінь знайдено

Це не недбалість виконавця. Запобіжники **існують і налаштовані правильно**:

- `.pre-commit-config.yaml` містить `ruff-format` (рядок 13);
- CI job `lint` запускає `pre-commit/action@v3.0.1`, тобто ті самі хуки.

Але жоден із них **жодного разу не спрацював** — бо `pre-commit` запускається
на коміті, CI на пуші, а в репозиторії **49 незакомічених позицій** і
**0 комітів попереду `origin`**. Уся робота семи пакетів досі не проходила ні
через хук, ні через CI.

**Тобто системний фікс — не новий гейт, а коміт.** Щойно робота піде через
`git commit`, `ruff-format` почне ловити це автоматично, і завдання класу И-2
більше не з'являтимуться.

⚠️ Виконавцю: цього пункту **не робити** — коміт робить власник своїм словом.
Записано, щоб причина була видима і щоб ніхто не будував ще один запобіжник
поверх робочого.
